# M1.4a — Interactive 799维+ONNX联合闭环（只计算、不控制）

目的：用已有 `ObservationBuilder` 和实际 `isaaclab::OrtRunner` 组成可独立复用的计算链，连续进行 `obs799 -> policy18 -> clipped_action -> next obs799`。这不是机器人运动闭环，也**不会发送** B2、Z1、MuJoCo 或 DDS 命令。

**前提：** 已通过M1.1 / M1.2 / M1.3；已有 `deploy/interactive_b2z1/build/b2z1_interactive_policy.onnx`。无需修改原有 `State_RLBase.cpp` / `main.cpp` / `z1_sdk_controller.cpp`。

## 运行（从仓库根目录）

```bash
cd /home/vi/lxy/unitree_ws/src/unitree_rl_mjlab
ORT_ROOT="$PWD/deploy/thirdparty/onnxruntime-linux-x64-1.22.0"
CXXFLAGS="-std=c++17 -O2 -Wall -Wextra"
mkdir -p deploy/interactive_b2z1/build

g++ $CXXFLAGS -I"$PWD/deploy/interactive_b2z1/include" \
  deploy/interactive_b2z1/src/interactive_observation.cpp \
  deploy/interactive_b2z1/src/interactive_pipeline.cpp \
  deploy/interactive_b2z1/tests/test_pipeline_safety.cpp \
  -o deploy/interactive_b2z1/build/test_pipeline_safety
./deploy/interactive_b2z1/build/test_pipeline_safety

g++ $CXXFLAGS -I"$PWD/deploy/interactive_b2z1/include" \
  -I"$PWD/deploy/include" -I"$ORT_ROOT/include" \
  deploy/interactive_b2z1/src/interactive_observation.cpp \
  deploy/interactive_b2z1/src/interactive_pipeline.cpp \
  deploy/interactive_b2z1/tests/test_pipeline_dry_run.cpp \
  "$ORT_ROOT/lib/libonnxruntime.so.1.22.0" \
  -Wl,-rpath,"$ORT_ROOT/lib" -pthread \
  -o deploy/interactive_b2z1/build/test_pipeline_dry_run

/home/vi/miniconda3/envs/b2z1_wbc/bin/python \
  deploy/interactive_b2z1/tests/test_pipeline_parity.py \
  --binary deploy/interactive_b2z1/build/test_pipeline_dry_run \
  --onnx deploy/interactive_b2z1/build/b2z1_interactive_policy.onnx \
  --frames 25
```

预计会出现两行PASS：

- `M1.4a PIPELINE SAFETY SELFTEST: PASS`
- `M1.4a CLOSED-LOOP PARITY: PASS`

如果超差，打印误差并记录，不要为了让PASS自动放宽阈值。对照Python是 **原始PyTorch 1.10** 环境，C++是当前项目的ONNX Runtime 1.22。连续反馈的误差可能比独立5帧高；这是检测新问题的目的。

## 边界与后续

- 测试使用同一组确定性合成机器人状态，每5帧重复，**不是**实际机器人运动轨迹；只验证动作参与下一个历史观测的计算链。
- `interactive_pipeline` 接收的是策略顺序 `FR FL RR RL, Z1关节1..6`，不读取实际B2/Z1通信；真实观测的姿态/坐标系/时间戳仍需另行验证。
- `faulted_` 是 **计算链错误闭锁**，不是执行器安全装置；它不执行零力矩/支撑/急停，调用者必须设计独立故障处置。
- 在未完成安全控制权检查及机械臂保护前，不得将本模块作为实机控制路径启动。原本存在的Z1保险丝熔断故障应独立排查原因。
- 下一阶段才修改实际B2Z1 FSM（优先只读旁路），并保证只通过Z1 SDK取得实机关节6维反馈；策略后6维动作绝不下发到Z1。
- 代码中没有关节目标命令生成，原有`go2_deploy`分支不受影响。
