# M1.4b-1 输入反馈适配层（仅离线）

## 目的与边界

前提：M1.4a 的 25 帧纯策略闭环已通过。

`interactive_feedback_adapter` 把**复制到本线程**的 B2 12 关节状态（SDK 电机顺序）与 Z1 SDK 6 关节反馈组合成 Interactive 的 18 关节策略顺序，并构造目标 EE 的训练观测坐标。它校验接收侧时间戳、双流时间偏差、四元数以及 NaN/Inf。没有任何硬件通信或电机命令，也不启动 FSM。

- B2 电机顺序：`FL FR RL RR`。策略顺序：`FR FL RR RL`；保留原仓库 `[3,4,5,0,1,2,9,10,11,6,7,8]`。
- Z1 6 关节状态必须由独立 Z1 SDK 的**真实反馈**提供；不允许拿 B2 末尾六个 motor_state 代替。
- 时间戳必须来自本机 `std::chrono::steady_clock` 的消息接收时间。同一时钟源内比较。没有时间戳或过期则拒绝。
- 目标 TCP 定义为 **B2 base 机体坐标系中的期望目标**；本模块从它计算训练所需 `ee_local_xyz`。该函数没有进行 Z1 FK/IK，也没有检查末端碰撞。
- 训练观测的名义偏置 `[0.20,0,0.09]` 与真实 Z1 安装 `[0.03,0,0.08]` **必须分别保留**。真实安装参数由未来的 FK/IK 及目标变换模块处理，不能偷换此项配置。
- `max_b2_age=100ms,max_z1_age=100ms,max_skew=50ms` 只是本阶段用于发现失效数据的可调整测试阈值；不是已经验证的实机安全数值。实际超时需结合 50Hz、真实消息延迟及现场控制需求设定。
- **特别警告**：现有 `CtrlFSM::run_()->post_run()` 每毫秒会发布 `lowcmd`。因此在 `State_RLBase` 内关闭 Interactive 输出 **不等于** 真正的只读模式。实际 shadow 模式必须从顶层阻止执行器发布，并禁止 Z1 `LOWCMD` 初始化和 `z1_ctrl` 辅助进程启动。

## 测试

在仓库根目录下执行：

```bash
mkdir -p deploy/interactive_b2z1/build

g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic \
  -Ideploy/interactive_b2z1/include \
  deploy/interactive_b2z1/src/interactive_observation.cpp \
  deploy/interactive_b2z1/src/interactive_feedback_adapter.cpp \
  deploy/interactive_b2z1/tests/test_feedback_adapter.cpp \
  -o deploy/interactive_b2z1/build/test_feedback_adapter

./deploy/interactive_b2z1/build/test_feedback_adapter
```

预期输出：`M1.4b FEEDBACK ADAPTER: PASS`。

## 后续实施（本包未包含）

1. 抽象 `SnapshotProvider`：明确 B2 `lowstate` 12 关节、Z1 独立 SDK 六关节和 EE goal 来源，复制出一致时间点的快照。
2. 用完整硬件模型检查反馈回调线程锁顺序、反馈年龄和帧间间隔；禁止 `BaseArticulation::update()`在实机模式访问 B2 的第13~18关节。
3. 新建 **独立进程** `b2z1_interactive_shadow`，只订阅反馈、计算观测与策略日志，不持有 `LowCmd` 发送器，且不启动 `Z1SdkController` LOWCMD，验证真实/通信式仿真的安全性后才能修改状态机的策略执行接口。
4. 若确实需要 Z1 SDK 的只读反馈，先确认官方 SDK 是否支持无控制权的订阅模式。当前 SDK 包装器构造即发 `PASSIVE -> LOWCMD`，不可直接用作只读消费者。
